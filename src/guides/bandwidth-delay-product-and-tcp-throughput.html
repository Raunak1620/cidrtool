When a file copy over a 1 Gbps WAN link only reaches 10 Mbps, the link is rarely the problem. The cause is usually the interaction between TCP and round-trip time.

The bandwidth-delay product

The bandwidth-delay product (BDP) is the amount of data that is "in flight" on a path at any moment:

BDP (bits) = bandwidth (bits per second) × round-trip time (seconds)

For a 1 Gbps link with a 50 ms round-trip time: 1,000,000,000 × 0.05 = 50,000,000 bits, which is 6,250,000 bytes, about 6.25 MB. To keep that link full, the sender must be able to have 6.25 MB of unacknowledged data outstanding.

How the TCP window limits speed

TCP will not send more than the receive window of unacknowledged data. So the maximum throughput of one connection is:

throughput ≤ window size ÷ round-trip time

Without window scaling, the TCP window field is 16 bits, so the largest window is 65,535 bytes. On the same 50 ms path: 65,535 × 8 = 524,280 bits, divided by 0.05 s gives about 10.5 Mbps. That matches the symptom above: the 1 Gbps link is idle most of the time.

How to fix it

  • Window scaling (RFC 7323) lets TCP advertise windows far above 64 KB. Modern operating systems enable it by default, but firewalls or middleboxes that strip TCP options can disable it.
  • Larger buffers. Socket buffers must be at least the BDP. On Linux, the net.ipv4.tcp_rmem and tcp_wmem settings cap how large the window can grow.
  • Parallel connections multiply the achievable throughput, which is why download tools open several streams.
  • Reduce RTT with a closer server, a CDN, or WAN acceleration.
  • Loss matters too. Even a small packet loss rate cuts throughput sharply on long paths, and the loss-based congestion control in classic TCP reacts strongly to it.

Measuring it

Measure RTT with ping and run a transfer test such as iperf3 with a single stream, then with several, to see whether the window is the bottleneck. Use the bandwidth calculator to convert between units and estimate transfer times.

Frequently asked questions

Does a faster link fix slow long-distance transfers?

Not by itself. If the window is the limit, throughput stays the same however fast the link is.

Is the BDP counted in bits or bytes?

Bandwidth is in bits per second, so the result is in bits. Divide by 8 to get bytes, which is what buffer sizes are measured in.

What RTT should I use?

The full round trip between the two hosts, as measured by ping, not the one-way delay.
