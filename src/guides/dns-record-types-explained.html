The Domain Name System maps names to data. Each piece of data is stored in a record with a type, a name, a value and a time to live (TTL), the number of seconds a resolver may cache it.

A and AAAA

These are the records most people think of. A domain can have several A records, and resolvers rotate through them, which gives a simple form of load balancing. Publish an AAAA record alongside an A record to support IPv6.

CNAME

A CNAME says "this name is an alias for that one". A name with a CNAME cannot have any other record type, which is why you cannot put a CNAME at the zone apex (such as example.com), where NS and SOA records must exist. Some providers offer an ALIAS or ANAME flattening feature to work around this.

MX and email records

MX records point to the mail servers for a domain. Lower priority numbers are tried first. Email authentication relies on TXT records: SPF lists the servers allowed to send, DKIM publishes the public key for signatures at a selector name, and DMARC at _dmarc.example.com says what receivers should do with failures.

NS and delegation

NS records name the servers that are authoritative for a zone. The parent zone holds NS records for the child, which is how delegation works. If those records disagree with the child's own NS set, resolution can fail in confusing ways, so check both.

PTR and reverse DNS

Reverse lookups use special zones. The address 192.0.2.10 is looked up as 10.2.0.192.in-addr.arpa. Mail servers often check that the sending IP has a PTR record, so set one for any server that sends email.

Troubleshooting tips

  • Query the authoritative server directly to avoid cached results.
  • After a change, the old value can persist for up to the old TTL, so lower the TTL before planned changes.
  • Use the DNS lookup tool to check any record type from a public resolver.

Frequently asked questions

Why can't I add a CNAME at the root of my domain?

The root already needs SOA and NS records, and a CNAME cannot coexist with other records on the same name.

What does TTL mean?

It is the number of seconds a resolver may cache a record before asking again.

How many MX records should I have?

At least one. Having two or more with different priorities gives a backup if the primary is down.
