Subnetting divides one IP network into several smaller networks, called subnets. You do it by borrowing bits from the host part of the address and using them as extra network bits. Every borrowed bit doubles the number of subnets and halves the number of addresses in each one. Once you can find the block size for a prefix, the rest is simple arithmetic.

Network bits and host bits

An IPv4 address is 32 bits long, usually written as four decimal numbers called octets. The prefix length, the number after the slash, says how many of the leading bits identify the network. The remaining bits identify individual hosts on that network. Two devices are on the same subnet when their network bits are identical.

Take 192.168.10.77/26. Written in binary the address is:

11000000.10101000.00001010.01001101
|------ 26 network bits ------|-6 host-|

The first 26 bits are the network part. The last 6 bits are the host part. Everything that follows is a way of working out where that boundary falls and what it means.

The subnet mask

The subnet mask writes the prefix as four octets. It has a 1 for every network bit and a 0 for every host bit. For /26 that is 26 ones followed by 6 zeros:

11111111.11111111.11111111.11000000  =  255.255.255.192

A full octet of eight ones is 255. An octet with only some ones is worth 256 minus 2(8 minus the number of ones). In the last octet of a /26 there are two ones, so the value is 256 − 26 = 256 − 64 = 192. The eight values that appear in a mask are 128, 192, 224, 240, 248, 252, 254 and 255. The /26 reference page lists the mask, wildcard and host count for this prefix, and the subnet chart covers every prefix.

Step by step: finding the subnet for 192.168.10.77/26

The question is: which subnet does 192.168.10.77 belong to, and what are its first address, last address and usable range?

  1. Count the host bits. 32 − 26 = 6 host bits. A subnet therefore contains 26 = 64 addresses.
  2. Find the interesting octet. This is the octet where the mask is neither 255 nor 0. Here it is the fourth octet, with a mask value of 192.
  3. Calculate the block size. 256 − 192 = 64. Subnets in this octet start at multiples of 64: 0, 64, 128 and 192.
  4. Find the network address. 77 lies between 64 and 127, so the subnet starts at 64. The network address is 192.168.10.64.
  5. Find the broadcast address. It is one less than the start of the next subnet. The next subnet starts at 128, so the broadcast address is 192.168.10.127.
  6. Find the usable range. Everything between the two: 192.168.10.65 to 192.168.10.126, which is 62 hosts.

You can confirm the network address with a bitwise AND of the address and the mask:

  01001101   (77, last octet of the address)
  11000000   (192, last octet of the mask)
  --------
  01000000   (64, last octet of the network address)

The first three octets of the mask are 255, so they pass through unchanged. That is why the network address is 192.168.10.64.

When the boundary is not in the last octet

The same method works for any prefix. Only the interesting octet changes. Consider 172.20.45.9/20:

  • The mask is 255.255.240.0, so the interesting octet is the third one, with a mask value of 240.
  • The block size is 256 − 240 = 16.
  • The third octet of the address is 45. The largest multiple of 16 that is not above 45 is 32, so the network address is 172.20.32.0.
  • The next subnet starts at 172.20.48.0, so the broadcast address is 172.20.47.255.
  • There are 12 host bits, so the subnet has 212 − 2 = 4,094 usable hosts.

Octets after the interesting one are 0 in the network address and 255 in the broadcast address.

Common mistakes

  • Forgetting the two reserved addresses. In a normal subnet the first address is the network address and the last is the broadcast address. Neither can be assigned to a host. See how many hosts are in a subnet for the /31 and /32 exceptions.
  • Mixing up the mask and the wildcard. The wildcard mask is the inverse of the subnet mask. For /26 the mask is 255.255.255.192 and the wildcard is 0.0.0.63.
  • Miscounting host bits. Always subtract the prefix from 32 before you do anything else.
  • Using the wrong octet. The interesting octet is the one where the mask changes from 255 to 0. For /26 it is the fourth, for /20 it is the third.

Frequently asked questions

Why do networks get subnetted?

Subnetting keeps broadcast domains small, lets you apply security policy between segments, makes it easier to summarize routes and avoids wasting addresses by giving every segment a block that fits it.

What is the fastest way to find a network address?

Find the interesting octet, work out the block size as 256 minus the mask value in that octet, and round the address octet down to the nearest multiple of the block size. Set all later octets to 0.

Do I need to do the maths in binary?

Not usually. Knowing the powers of two (128, 64, 32, 16, 8, 4, 2, 1) and the eight mask values is enough for the block size method. Binary is useful for understanding why the method works and for checking unusual cases.

How is subnetting different from supernetting?

Subnetting splits a network into smaller ones by lengthening the prefix. Supernetting, also called route aggregation, combines several networks into a larger one by shortening the prefix. The CIDR notation guide explains aggregation.
