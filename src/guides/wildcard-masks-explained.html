A wildcard mask is a 32-bit pattern used by Cisco IOS in access lists and in the network command of OSPF and EIGRP. It works like a subnet mask turned upside down: a 0 bit means the address bit must match and a 1 bit means the bit is ignored.

Subnet mask versus wildcard mask

A subnet mask of 255.255.255.0 says "the first 24 bits are the network". The matching wildcard mask is 0.0.0.255, which says "the first 24 bits must match, the last 8 can be anything". For any contiguous mask, the wildcard is the subnet mask subtracted from 255.255.255.255.

How to calculate it

Subtract each octet of the subnet mask from 255.

  • /24, 255.255.255.0 gives 0.0.0.255
  • /26, 255.255.255.192 gives 0.0.0.63
  • /20, 255.255.240.0 gives 0.0.15.255
  • /30, 255.255.255.252 gives 0.0.0.3

A shortcut: the last number of a wildcard is always the block size minus 1. A /26 has a block size of 64, so the wildcard is 63.

Using wildcard masks in an ACL

To permit the subnet 192.168.10.0/24 in a standard access list:

access-list 10 permit 192.168.10.0 0.0.0.255

The router compares the first three octets of each packet's source address and ignores the last. To match a single host, use a wildcard of 0.0.0.0 or the keyword host. To match everything, use 0.0.0.0 255.255.255.255 or the keyword any.

Using them in OSPF

The network command decides which interfaces run OSPF. For an interface with address 10.1.2.5/24:

router ospf 1
 network 10.1.2.0 0.0.0.255 area 0

Any interface whose address falls inside 10.1.2.0/24 joins area 0. The mask only selects interfaces; the interface still advertises its own configured prefix length.

Non-contiguous wildcard masks

Wildcard masks are not required to be contiguous. The wildcard 0.0.0.254 ignores every bit of the last octet except the lowest, so with an address of 10.0.0.1 it matches every odd host address. Engineers occasionally use this to match several subnets in one ACL line, for example 172.16.0.0 0.0.254.255. Use it with care, because the result is hard to read and easy to get wrong.

Where wildcard masks are not used

Juniper, Linux iptables, most firewalls and cloud security groups use CIDR notation such as 10.1.2.0/24. If you move a rule from Cisco IOS to another platform, convert the wildcard mask to a prefix length by counting the 0 bits.

Frequently asked questions

What is the wildcard mask for 255.255.255.0?

0.0.0.255.

What is the wildcard mask for a /32?

0.0.0.0, which means all 32 bits must match, so it selects exactly one host.

Is the wildcard mask the same as the inverse mask?

Yes. The terms are used interchangeably.

Do newer Cisco platforms still use wildcard masks?

Classic IOS and IOS-XE ACLs and routing network statements do. Many newer platforms and NX-OS accept CIDR prefix lengths in ACLs as well.
