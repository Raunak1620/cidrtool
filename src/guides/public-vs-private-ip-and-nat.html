A public IP address is unique across the internet and can be routed anywhere. A private IP address comes from a reserved range such as 192.168.0.0/16 and only has meaning inside one network. Many private networks reuse the same ranges, so private addresses cannot be reached from outside directly.

Why the two exist

IPv4 has about 4.3 billion addresses, which is far fewer than the number of connected devices. Private addressing plus NAT lets a whole home or company share one or a few public addresses.

How NAT works

A NAT device, usually your router or firewall, sits between the private network and the internet. When a private host sends a packet out, the device replaces the source address with its own public address and records the mapping. When the reply returns, it uses the record to restore the private destination address and forward the packet.

PAT, or NAT overload

Most home and office networks use port address translation. Many private hosts share one public address, and the device tells their connections apart by rewriting the source port. For example, 192.168.1.10:51000 and 192.168.1.11:51000 might become 203.0.113.5:40001 and 203.0.113.5:40002. This is what the "NAT overload" command configures on Cisco routers, and it is why the address that a site like What Is My IP shows is your router's public address, not your device's.

Types of NAT

  • Static NAT maps one private address to one public address permanently. It is used to publish a server.
  • Dynamic NAT maps private addresses to a pool of public addresses on demand.
  • PAT maps many private addresses to one public address using ports.
  • Port forwarding sends inbound traffic for a specific public port to an internal host.
  • Carrier-grade NAT is done by an ISP, so several customers share one public address. Port forwarding does not work through it.

Problems NAT causes

  • Inbound connections need port forwarding, because the device has no mapping for unsolicited traffic.
  • Protocols that carry IP addresses inside the data, such as some VoIP and FTP modes, need an application-layer helper.
  • Overlapping private ranges break VPNs and mergers, since both sides use the same addresses.
  • Logs show only the public address, so tracing activity to one device needs the NAT translation table.

NAT is not a firewall

NAT blocks unsolicited inbound traffic as a side effect, but it was not designed for security. A stateful firewall is what provides protection, and with IPv6 you rely on it because NAT is usually not used.

Frequently asked questions

Why is my public IP different from my device's IP?

Your device has a private address. Your router translates it to the public address it holds from your ISP.

Does a VPN change my public IP?

Yes. Traffic leaves from the VPN provider's public address instead of your router's.

Can two devices have the same private IP?

Yes, if they are on different networks. They cannot share an address on the same network.

Does IPv6 need NAT?

Not normally. There are enough addresses for every device to have a globally routable one.
