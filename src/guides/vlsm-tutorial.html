VLSM, variable length subnet masks, means using different prefix lengths inside one address block. Instead of giving every segment the same size, you give each one the smallest subnet that fits its hosts. The method is to sort the requirements from largest to smallest and then assign subnets one after another from the start of the block.

Why use VLSM

Equal-sized subnets waste addresses. If one department has 60 devices and a WAN link has 2, giving both a /26 leaves the link with 62 unused addresses. VLSM lets the link use a /30 and keeps the rest of the block free for other networks. It also makes address plans easier to summarize, because you control where each block starts.

VLSM needs a routing protocol that carries the mask with each route. OSPF, EIGRP, IS-IS, BGP and RIPv2 do. Classful protocols such as RIPv1 do not.

The method

  1. List every subnet you need with its number of hosts. Include point-to-point links.
  2. Work out the prefix for each one. Find the smallest h where 2h − 2 is at least the host count. The prefix is 32 − h. The host count guide explains this step in detail.
  3. Sort the list from largest subnet to smallest.
  4. Assign the first subnet at the start of the address block. Each next subnet starts at the address after the previous one ends.
  5. Record what is left. The unused space after the last subnet is available for growth or new networks.

Worked example

You have 192.168.10.0/24 and need four networks:

  • Sales: 60 hosts
  • Engineering: 28 hosts
  • Management: 10 hosts
  • WAN link between two routers: 2 hosts

Each subnet begins right after the previous one. Sales takes 64 addresses (.0 to .63), so Engineering starts at .64. Engineering takes 32 (.64 to .95), so Management starts at .96. Management takes 16 (.96 to .111), so the WAN link starts at .112 and takes 4 (.112 to .115).

Step 3: record the free space

The four subnets use 64 + 32 + 16 + 4 = 116 addresses. The block from 192.168.10.116 to 192.168.10.255 is still free. That is 140 addresses. The next WAN link, if you add one, would be 192.168.10.116/30 with usable addresses .117 and .118 and broadcast .119.

For comparison, if all four networks had used a /26, the plan would use all 256 addresses of the /24 and leave nothing for growth. You can reproduce this plan, or enter your own requirements, in the VLSM calculator.

Why you allocate the largest subnet first

A subnet must start on a multiple of its own size. A /26 must start at .0, .64, .128 or .192. If you place small subnets first, you can force a larger one to skip ahead and strand addresses.

Suppose you put the WAN link first at 192.168.10.0/30, which uses .0 to .3. The Sales /26 cannot start at .4. The next valid start is .64. The addresses from .4 to .63, which are 60 addresses, would sit unused unless you filled them with other small subnets. Placing the largest block first means every later block lands on a valid boundary without gaps.

Point-to-point links and /31

The example uses a /30 for the WAN link, the traditional choice. If both devices support RFC 3021, a /31 gives the same two usable addresses using half the space. That saves 2 addresses per link, which adds up on a network with many links. Use it only where you have confirmed support on both ends.

Tips for a plan that lasts

  • Add headroom. Size each subnet for the number of hosts you expect later, not only the count today.
  • Keep related subnets together. Subnets for one site or one function that sit in one contiguous block can be summarized into a single route. The CIDR notation guide explains the alignment rules.
  • Reserve space deliberately. Leave a documented gap for future subnets rather than filling the block to the last address.
  • Check for overlaps. Two subnets must never share an address. Sorting by size and allocating in sequence avoids this.
  • Document the plan. Record the subnet, mask, purpose and gateway for each entry.

Frequently asked questions

What does VLSM stand for?

Variable length subnet masks. It means using more than one prefix length inside the same address block, so each subnet can be sized for its own needs.

Is VLSM the same as CIDR?

No, but they are related. CIDR is the classless addressing and routing model that lets prefixes be any length. VLSM is the practice of using different prefix lengths inside one network when you subnet it.

Why start with the largest subnet?

Because each subnet must begin on a boundary that is a multiple of its size. Allocating the largest first keeps the pointer aligned for every smaller subnet and avoids unusable gaps.

Does my routing protocol need to support VLSM?

Yes. OSPF, EIGRP, IS-IS, BGP and RIPv2 carry the subnet mask in each route and work with VLSM. RIPv1 is classful and does not.
