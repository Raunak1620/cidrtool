Why convert IP addresses?

An IPv4 address is just a 32-bit number. Dotted decimal is the friendly way to write it, but other forms show up in logs, databases, packet captures, firewall rules and exploit write-ups. Databases often store addresses as integers because ranges become simple numeric comparisons. Packet captures show hexadecimal. Binary makes subnet boundaries visible.

How the conversion works

Each octet is a byte, so 192.168.1.1 equals 192 × 256³ + 168 × 256² + 1 × 256 + 1 = 3232235777. In hexadecimal that is 0xC0A80101, and in binary 11000000.10101000.00000001.00000001. The converter accepts any of these and shows all of them.

IPv6 forms

IPv6 addresses can be written in full (2001:0db8:0000:0000:0000:0000:0000:0001) or compressed by dropping leading zeros in each group and replacing the longest run of zero groups with :: (2001:db8::1). Both mean the same address. The tool also shows the integer value, the binary groups and the ip6.arpa name used for reverse DNS.

Special representations

  • IPv4-mapped IPv6 (::ffff:a.b.c.d): how dual-stack sockets represent IPv4 clients.
  • 6to4: embeds an IPv4 address in the 2002::/16 prefix for automatic tunnelling.
  • Solicited-node multicast: the multicast address used by IPv6 neighbour discovery, built from the last 24 bits of a unicast address.

Frequently asked questions

How do I convert an IP address to a decimal number?

Multiply the octets by 256³, 256², 256 and 1 and add them. Or paste the address above and copy the decimal integer.

Why does 127.1 or 0177.0.0.1 sometimes work in a browser?

Some software accepts shortened or octal forms. These are ambiguous and are sometimes abused to bypass filters, so this tool only accepts the unambiguous formats.

How do I write a reverse DNS name?

For IPv4, reverse the octets and append .in-addr.arpa. For IPv6, reverse the 32 hex digits, separate each with a dot and append .ip6.arpa. The converter generates both.
