How the port check works

When you press the button, a server on the internet tries to open a TCP connection to each port you listed on your public IP address. The result is one of three states.

  • Open. A connection was accepted, so a service is listening and the path through your firewall and router is open.
  • Closed. Your IP answered with a refusal. The traffic reached you, but no service listens on that port.
  • No response. Nothing came back before the timeout. This is the usual result for a port blocked by a firewall, or one that is not forwarded to an inside device.

Testing port forwarding

  1. Start the service on your device and confirm it works locally, for example by opening http://localhost:8080.
  2. Create the port forward on your router from the external port to your device's private address, and give the device a fixed IP or a DHCP reservation.
  3. Allow the port in the device's own firewall.
  4. Run this check. If the port shows as open, forwarding works.

Why a port may show as closed or not respond

  • The service is not running, or listens only on 127.0.0.1 and not on the network.
  • The router forward points at the wrong internal address or protocol (TCP versus UDP).
  • The device firewall blocks the port.
  • Your ISP uses carrier-grade NAT, so your router has no public address of its own. Check whether the WAN address on your router matches the one shown by What Is My IP. If they differ, port forwarding cannot work, and you need a VPN or tunnel instead.
  • Your ISP blocks common ports such as 25, 80 or 445 on residential lines.

This checker tests TCP only. It cannot test UDP, because UDP has no handshake that reports whether a port is open.

Security advice

An open port is an exposed service. Keep only the ports you need open, keep software updated, and use strong authentication. Never expose remote desktop, SMB, databases or Telnet directly to the internet. Put administrative access behind a VPN instead. See the port numbers reference for what each common port is used for.

Frequently asked questions

Can I check another person's server or IP address?

No. The checker only tests the public IP address of the connection you are using. This prevents it from being used to scan other people's systems.

Why does it test my IP and not a host name?

Because it checks the network you are on. To test a server at another location, run the check from a device on that network.

Is a closed port safer than one with no response?

A port that gives no response reveals less, because it does not confirm that a host exists. A closed port still shows your IP is active. Both mean no service is reachable.

Do you store my IP address?

This site does not save it or the results. The check reads the IP address of your request to run the test and returns the result to you. Like any web host, the hosting provider may keep standard technical request logs.
