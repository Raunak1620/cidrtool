How this ping test works

A traditional ping sends an ICMP echo request and times the reply. Web pages cannot send ICMP, so this test sends small HTTPS requests from your browser and times how long each takes to get a response. The first request is used to open the connection and is not counted. After that, the browser reuses the connection, so each timing is close to one network round trip plus a little server processing time.

What the numbers mean

  • Average latency is the typical round-trip time. Under 30 ms is excellent, 30 to 80 ms is fine for most uses, and above 150 ms is noticeable in calls and games.
  • Jitter is how much the latency varies between consecutive requests. A steady 40 ms is better than a line that swings between 10 and 120 ms.
  • Failed requests are requests that got no response in four seconds. Any sustained failure rate points to packet loss, a congested link or a flaky Wi-Fi connection.

How it differs from ICMP ping

  • HTTPS timings include a small amount of server processing time, so they read a few milliseconds higher than ICMP to the same host.
  • Some networks treat ICMP differently from web traffic, so a host can answer web requests while blocking ping, or the reverse.
  • The test cannot report a packet loss figure in the strict sense. A failed request can come from loss, a slow server or a blocked request.

For true ICMP tests use the command line: ping -c 20 example.org on Linux and macOS, or ping -n 20 example.org on Windows.

Frequently asked questions

Why can't this tool run a real ICMP ping or a traceroute?

Browsers do not let web pages create raw network packets or set the TTL field. Doing so would need a server that pings on your behalf, which would measure the server's connection and not yours. Use the traceroute analyzer to interpret the output of the real command.

Why is the first ping not counted?

It includes DNS lookup, the TCP handshake and the TLS handshake, which can take several round trips. Later requests reuse that connection.

Which target should I choose?

Pick a large provider such as Cloudflare or Google to test your own connection, because they have servers close to almost everyone. Use a custom host to check the path to a specific site.

Is anything sent to your servers?

No. Requests go from your browser straight to the target, and nothing is stored.
