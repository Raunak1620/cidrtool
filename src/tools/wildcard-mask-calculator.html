What is a wildcard mask?

A wildcard mask is the bitwise inverse of a subnet mask. Where a subnet mask uses 1 bits for the network part, a wildcard mask uses 0 bits to mean "this bit must match" and 1 bits to mean "this bit can be anything". The subnet mask 255.255.255.0 becomes the wildcard mask 0.0.0.255. Cisco IOS access lists and the network statements in OSPF and EIGRP use wildcard masks, which is why engineers keep converting between the two.

How to calculate a wildcard mask

Subtract each octet of the subnet mask from 255. For 255.255.240.0: 255 − 255 = 0, 255 − 255 = 0, 255 − 240 = 15 and 255 − 0 = 255, so the wildcard mask is 0.0.15.255. For a prefix length, the wildcard has 32 − prefix trailing 1 bits, so a /20 leaves 12 host bits and the wildcard is 0.0.15.255.

The host and any keywords

In Cisco ACLs, host 10.1.1.1 is shorthand for 10.1.1.1 0.0.0.0 (a /32), and any is shorthand for 0.0.0.0 255.255.255.255 (a /0). The calculator uses these forms in the snippets it generates.

Frequently asked questions

What is the wildcard mask for /24?

0.0.0.255. A /24 has 8 host bits, so the last octet of the wildcard is all ones.

What is the wildcard mask for a single host?

0.0.0.0, which means every bit must match. Cisco lets you write host x.x.x.x instead.

Can a wildcard mask be non-contiguous?

Yes. Unlike subnet masks, wildcard masks do not have to be contiguous, which allows tricks such as matching only odd or even subnets. This calculator accepts contiguous masks only, because those correspond to real CIDR blocks.

Do all vendors use wildcard masks?

No. Cisco IOS uses them in ACLs and routing network statements. Juniper, Linux and most firewalls use prefix lengths or subnet masks instead.
